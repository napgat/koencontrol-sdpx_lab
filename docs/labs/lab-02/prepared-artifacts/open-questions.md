# Open Questions — PairEval
Open Question ไม่ใช่ requirement ที่เรารู้คำตอบแล้ว แต่คือ “จุดที่ requirement ยังไม่บอกชัด จึงห้ามเดาเอง”

## Q1: Deadline ใช้ timezone ใด
- **Question:** Assignment deadline ต้องตีความเป็น timezone ของผู้สอน, timezone ของรายวิชา, หรือ UTC?
- **Why it matters:** หาก student และ instructor อยู่คนละ timezone ระบบอาจปิดการ submit ก่อนหรือหลังเวลาที่เข้าใจ
- **Decision needed from:** Product owner / instructor

## Q2: หลังเปลี่ยนกลุ่มและ re-generate pairs จะจัดการ draft เดิมอย่างไร
- **Question:** Draft ที่ยังไม่ submit ต้องถูก invalidate ทันทีเหมือน submission หรือให้ student นำคำตอบเดิมกลับมาใช้ได้?
- **Why it matters:** มีผลต่อกฎการเก็บข้อมูล, หน้าจอแจ้งเตือน และ API สำหรับอ่าน draft
- **Decision needed from:** Product owner / instructor

## Q3: หลังเริ่มมีคำตอบแล้ว แก้ไข criteria ของ Assignment ได้หรือไม่
- **Question:** Instructor สามารถเพิ่ม, ลบ, เปลี่ยนน้ำหนัก หรือเปลี่ยนชื่อ criteria หลังนักศึกษาเริ่ม submit แล้วได้หรือไม่?
- **Why it matters:** การเปลี่ยน criteria อาจทำให้ pair assignments และคะแนนที่คำนวณไว้ไม่สอดคล้องกัน
- **Decision needed from:** Product owner / instructor

# Comment
ภาพรวมของ PairEval คือ:

- อาจารย์สร้าง **Assignment** เช่น “ประเมินงานกลุ่มครั้งที่ 1”
- กำหนด **criteria** เช่น ความครบถ้วน 40%, UX 60%
- ระบบสร้างคู่ให้ผู้เรียนเปรียบเทียบ
- ผู้เรียนกด **Save** เพื่อเก็บร่าง หรือ **Submit** เพื่อส่งคำตอบจริง
- ระบบนำคำตอบไปคำนวณคะแนน

### Q1: Deadline ใช้ timezone ใด

สมมติอาจารย์ตั้ง deadline `23:59` วันที่ 10 กันยายน

คำถามคือ `23:59` ของเวลาอะไร?

- เวลาไทย (UTC+7)
- เวลาเครื่องของผู้สอน
- เวลา UTC

ถ้าไม่กำหนด นักศึกษาที่อยู่คนละประเทศอาจเห็นเวลาปิดไม่ตรงกัน และ backend อาจรับหรือปฏิเสธ submission ผิดเวลา

ข้อเสนอที่เหมาะกับรายวิชานี้: กำหนด timezone ของรายวิชาให้ชัด เช่น `Asia/Bangkok` แล้วทั้งหน้าจอและ API ใช้ค่าเดียวกัน

### Q2: เปลี่ยนกลุ่มแล้ว draft เดิมเป็นอย่างไร

เมื่ออาจารย์ย้ายสมาชิกกลุ่ม ระบบต้องสร้างคู่ประเมินใหม่ เพราะคู่เดิมอาจไม่ถูกต้องแล้ว

PRD บอกชัดว่า **submission ที่ส่งแล้ว** ต้อง invalidate แต่ยังต้องตัดสินใจว่า **draft ที่กด Save แต่ยังไม่ Submit** จะเป็นอย่างไร

ตัวอย่าง:

- เดิม A อยู่กลุ่ม 1 และ Save คำตอบไว้
- อาจารย์ย้าย A ไปกลุ่ม 2
- ระบบสร้าง pairs ใหม่

คำถามคือ draft เดิมควรถูกลบทิ้ง/ทำให้ใช้ไม่ได้ด้วยไหม หรือให้ A กลับมาใช้คำตอบนั้นต่อ?

ข้อเสนอที่ปลอดภัย: invalidate draft ด้วย เพราะ draft อ้างอิง pair เดิมที่อาจไม่มีอยู่แล้ว

### Q3: แก้ criteria หลังเริ่มประเมินได้ไหม

criteria คือหัวข้อที่ใช้เปรียบเทียบ เช่น:

```
ความครบถ้วน 40%
User Experience 60%
```

ปัญหาเกิดเมื่อมีนักศึกษาส่งคำตอบไปแล้ว แต่อาจารย์ต้องการ:

- เพิ่ม criteria ใหม่
- ลบ criteria เดิม
- เปลี่ยนน้ำหนักจาก 40% เป็น 70%
- แก้ชื่อ criteria

คะแนนเดิมและ pair assignments ถูกสร้างตาม criteria เก่า จึงอาจคำนวณผิดหรือเปรียบเทียบกันไม่ยุติธรรม

ข้อเสนอที่ปลอดภัย: แก้ criteria ได้เฉพาะก่อนสร้าง pairs หรือก่อนมีการ submit ครั้งแรก หลังจากนั้นให้สร้าง Assignment ใหม่แทน
