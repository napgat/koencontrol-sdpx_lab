# AI Review สำหรับ WS-08 — PairingService.generatePairAssignments

ตรวจจาก `src/services/pairing-service.ts` ณ 26 กันยายน 2026 เป็นการอ่านโค้ด ยังไม่ได้แก้หรือทดสอบประสิทธิภาพจริง

| ระดับ | ประเด็น | ทำไมจึงสำคัญ |
|---|---|---|
| High | ตรวจว่ามีข้อมูลเดิมด้วย `findByAssignmentId` แล้วค่อย `saveMany` แยกกัน | หากมีคำขอพร้อมกัน ทั้งสองคำขออาจตรวจว่า “ยังไม่มี” และบันทึกคู่ซ้ำได้ ต้องพิสูจน์ด้วย repository จริงและป้องกันที่ชั้นข้อมูล |
| High | ไม่ตรวจ ID กลุ่มซ้ำหรือข้อมูลผู้ประเมินว่าอยู่ในกลุ่มที่ถูกต้อง | ข้อมูลนำเข้าผิดอาจสร้างคู่ที่ไม่สมเหตุผลหรือเลือกผู้ประเมินที่ไม่ควรมีสิทธิ์ |
| Medium | ใช้ `evaluators.find` เลือกคนแรกที่เข้าเงื่อนไขเสมอ | เมื่อมีผู้ประเมินให้เลือกหลายคน คนต้นรายการอาจได้รับงานมากกว่าคนอื่น |
| Medium | การค้นหาผู้ประเมินทำซ้ำทุกคู่และทุกเกณฑ์ | เวลาในการทำงานเพิ่มตามจำนวนกลุ่ม เกณฑ์ และผู้ประเมิน; ยังไม่มีผลวัดเพื่อสรุปว่าเป็น bottleneck จริง |
| Medium | ไม่ตรวจว่า `criteria` มีรายการและ ID ไม่ซ้ำ | อาจบันทึกศูนย์คู่หรือสร้างคู่ซ้ำตามเกณฑ์ที่ซ้ำ โดยไม่แจ้งข้อผิดพลาดที่ชัดเจน |
| Low | มีบรรทัดเงื่อนไขเก่าที่ comment ค้างไว้ | ทำให้คนอ่านลังเลว่าเงื่อนไขปัจจุบันตั้งใจใช้แบบใด |
| Low | `PairingRuleError` ไม่มีรหัสข้อผิดพลาดแยกตามสาเหตุ | API ที่จะเรียกใช้ต้องพึ่งข้อความเพื่อแยกกรณี ซึ่งเปลี่ยนได้ง่าย |

ด้านความปลอดภัย function นี้ยังไม่ใช่ HTTP endpoint จึงสรุปไม่ได้ว่าระบบเปิดให้ผู้ไม่มีสิทธิ์เรียกใช้งานหรือไม่ เมื่อสร้าง API ต้องตรวจสิทธิ์ที่ขอบเขต request ก่อนเรียก service และตรวจข้อมูลนำเข้าฝั่ง server

สิ่งที่ควรตรวจใน WS-08: ทดสอบคำขอพร้อมกันกับ repository จริง, ทดสอบข้อมูล ID ซ้ำ/ข้อมูลผู้ประเมินผิด, วัดเวลาทำงานเมื่อจำนวนกลุ่มเพิ่ม และกำหนดกติกากระจายงานผู้ประเมินก่อน refactor
